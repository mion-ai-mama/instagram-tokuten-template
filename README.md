# 特典ページテンプレート（Instagramリール用）

Instagramリールのフォロワーに配布する「特典ページ」を、GitHub Pagesで無料公開するための
テンプレートです。コードの知識がなくても、`js/content.js` というファイル1つを
書き換えるだけで、新しい特典ページを作れるようになっています。

このREADMEは、パソコンの操作にあまり詳しくない方でも迷わないように、
専門用語をできるだけ避けて説明しています。

## 1. このテンプレートの目的

Instagramのリール動画を見てくれた人に、「もっと詳しい内容」を無料の特典として
渡すための1枚ページ（LP＝ランディングページ）です。

これまでnoteで作っていた特典を、このテンプレートを使うことで

- スマートフォンで読みやすい
- 見た目が整っている
- 無料で公開できる（GitHub Pages）
- 次回以降も使い回せる

という形で作れるようになります。

---

## 2. 新しい特典ページの作り方（全体の流れ）

新しいリール用に特典ページを作るときは、次の順番で進めます。

1. このリポジトリを「テンプレート」として複製する（[3章](#3-use-this-templateの使い方)）
2. `js/content.js` の文章を新しい内容に書き換える（[5章](#5-contentjs-の編集方法)）
3. 必要なら画像・動画を差し替える（[10章](#10-画像を追加する方法) [11章](#11-動画を追加する方法)）
4. GitHub Pagesで公開する（[12章](#12-github-pagesで公開する方法)）
5. スマホで見え方を確認する（[15章](#15-スマートフォン表示の確認方法)）

コードを1から書く必要はありません。**基本的に `content.js` を書き換えるだけ**です。

---

## 3. 「Use this template」の使い方

GitHubには、このリポジトリをそのまま複製して新しいリポジトリを作れる
「テンプレート機能」があります。

1. このリポジトリのGitHubページを開く
2. 右上あたりにある緑色の **「Use this template」** ボタンをクリック
3. 「Create a new repository」を選ぶ
4. 新しいリポジトリの名前を入力する（例：`no14-video-analysis`）
   - 名前は半角英数字とハイフンがおすすめです（日本語は避けてください）
5. 「Create repository」をクリックする

これで、今のテンプレートの中身がそのまま入った、新しいリポジトリが作られます。
元のテンプレートには影響しません。

> 💡 「テンプレートリポジトリ」に設定する方法は、GitHubの
> `Settings` → `General` → `Template repository` にチェックを入れるだけです。
> （このテンプレートは公開時にこの設定を行っています）

## 4. 変更するファイル

新しい特典ページを作るとき、**基本的に触るのは1つだけ**です。

| ファイル | 説明 | 編集頻度 |
|---|---|---|
| `js/content.js` | ページの文章・プロンプト・リンクをまとめたファイル | **毎回編集する** |
| `assets/images/` `assets/videos/` | 画像・動画ファイルの置き場所 | 必要なときだけ |
| `index.html` の `<head>` 内 | SEO用の説明文（検索結果に出る文章） | できれば毎回確認 |
| `css/style.css` | 色やデザイン | 基本的に編集不要 |
| `js/script.js` | ページの動き（コピー機能など） | 編集不要 |

---

## 5. content.js の編集方法

`js/content.js` をテキストエディタ（メモ帳や、GitHub上の鉛筆アイコンでも可）で開くと、
日本語の文章がたくさん並んでいます。

例えばこの部分：

```js
hero: {
  label: "AI初心者さん向け",
  titleLine1: "AIで人気動画を",
  titleLine2: "分析する方法",
  ...
```

`"　　"`（ダブルクォーテーションで囲まれた部分）の中の日本語だけを書き換えてください。

**触ってはいけない部分**：

- `:`（コロン）
- `,`（カンマ）
- `{ }`（波かっこ）
- `[ ]`（角かっこ）
- `<br>`（改行を表すタグ。残したまま、前後の文字だけ変えればOK）

書き換えたら保存して、`index.html` をブラウザで開けば、変更が反映されているか
確認できます。

## 6. タイトルの変更方法

`content.js` の中の `hero` の部分と、`meta` の部分を書き換えます。

```js
meta: {
  pageTitle: "（ブラウザのタブに表示されるタイトル）",
  description: "（検索結果やSNSに表示される説明文）",
  ...
},

hero: {
  label: "（タイトルの上に出る小さいラベル）",
  titleLine1: "（メインタイトル1行目）",
  titleLine2: "（メインタイトル2行目）",
  subtitleLine1: "（サブタイトル1行目）",
  subtitleLine2: "（サブタイトル2行目）",
  ...
}
```

> ⚠️ `meta.pageTitle` と `meta.description` は、検索エンジンやSNSがページの内容を
> 正しく認識できるように、**`index.html` の `<head>` 内にある同じ内容の部分も
> あわせて書き換える**ことをおすすめします（JavaScriptを読み込めないロボットが
> 見に来ることがあるためです）。`index.html` の上のほうにある
> `<title>` タグと `<meta name="description" ...>` タグを探して、同じように
> 書き換えてください。

## 7. STEPの変更方法

`content.js` の `steps` の部分（配列になっています）を書き換えます。

```js
steps: [
  {
    number: "STEP 1",
    title: "（STEPの見出し）",
    paragraphs: ["（本文の段落1）", "（本文の段落2）"],
    list: ["（箇条書き1）", "（箇条書き2）"],
    afterParagraphs: ["（箇条書きのあとの段落）"],
    note: null, // 補足ボックスが必要な場合は { label: "補足", text: "（補足文）" } に変更
  },
  ...
]
```

STEPを増やしたい場合は、`index.html` 側にも `id="step4"` のようなセクションを
追加する必要があります（少し専門的な作業になるため、迷ったら3STEP構成のまま
使うことをおすすめします）。

## 8. プロンプトの変更方法

`content.js` の `mainPrompt`（メインのプロンプト）と `extraQuestions`（追加質問5つ）を
書き換えます。

```js
mainPrompt: {
  heading: "（見出し）",
  description: "（説明文）",
  promptText: `（ここにプロンプト本文を書く。改行はそのまま反映されます）`,
  buttonText: "この指示文をコピーする",
  copiedText: "コピーしました",
},
```

`promptText` は バッククォート（\` \`）で囲まれています。この中の文章はそのまま
改行して書いてOKです。

追加質問は `extraQuestions.questions` に文章を並べます。数を増減させたい場合は、
配列の行を増やしたり減らしたりしてください（自動でカードの数が変わります）。

## 9. CTAリンクの変更方法

ページ最後の案内ボタン（例：「AIマネタイズの教科書を受け取る」）のリンク先は、
`content.js` の `cta.buttonUrl` の**1か所だけ**を変更すれば反映されます。

```js
cta: {
  ...
  buttonUrl: "https://example.com/", // ← ここをLINE登録URLなどに変更
},
```

HTML側を探して書き換える必要はありません。

## 10. 画像を追加する方法

1. `assets/images/` フォルダの中に、画像ファイル（jpg・png・webpなど）を入れる
2. 使いたい場所に応じて、`content.js` 内のパスを書き換える
   - 例：OGP画像（SNSシェア用）→ `meta.ogpImage`
   - 例：動画のサムネイル → `exampleVideo.local.poster`
3. ファイル名は半角英数字がおすすめです（日本語ファイル名はトラブルの原因になりやすいです）

## 11. 動画を追加する方法

**動画は必須ではありません。** 動画がない特典の場合は、`content.js` の
`exampleVideo.showVideo` を `false` のままにしておけば、動画セクションごと
自動的に非表示になり、前後のセクションが自然につながります（レイアウトは崩れません）。

```js
exampleVideo: {
  showVideo: false, // 動画を使う場合だけ true に変更してください
  ...
}
```

動画を使いたい場合は `showVideo: true` に変更したうえで、2つの方法から選べます。
`content.js` の `exampleVideo.mode` を `"local"` か `"youtube"` に切り替えてください。

### 方法A：動画ファイルを直接アップロードする（`mode: "local"`）

1. `assets/videos/` フォルダに動画ファイル（mp4形式）を入れる
2. `content.js` の `exampleVideo.local.src` にファイル名を指定する

```js
exampleVideo: {
  mode: "local",
  local: {
    src: "assets/videos/example.mp4",
    poster: "assets/images/video-poster.jpg",
  },
  ...
}
```

> ⚠️ **動画ファイルの容量に注意してください。**
> GitHubは1ファイルあたり100MBまでという制限があり、また容量が大きい動画は
> ページの表示が遅くなります。**目安として20MB以下**（できれば10MB前後）に
> 圧縮することをおすすめします。スマートフォンの動画編集アプリや、
> 無料の動画圧縮サイトで容量を小さくしてからアップロードしてください。

### 方法B：YouTubeの限定公開動画を埋め込む（`mode: "youtube"`）

動画の容量が大きい場合は、YouTubeに「限定公開」でアップロードして、
そのリンクを埋め込む方法もおすすめです（GitHubの容量制限を気にしなくて済みます）。

1. YouTubeに動画を「限定公開」でアップロードする
2. 動画の埋め込み用URL（`https://www.youtube.com/embed/動画ID` の形式）を確認する
3. `content.js` を以下のように書き換える

```js
exampleVideo: {
  mode: "youtube",
  youtube: {
    embedUrl: "https://www.youtube.com/embed/動画ID",
  },
  ...
}
```

## 12. GitHub Pagesで公開する方法

1. GitHubで、複製した自分のリポジトリを開く
2. 上部メニューの **「Settings」** をクリック
3. 左側のメニューから **「Pages」** をクリック
4. 「Build and deployment」の「Source」で **「Deploy from a branch」** を選ぶ
5. 「Branch」で **「main」**（またはご自身のメインブランチ名）と **「/ (root)」** を選び、
   「Save」をクリック
6. 数分待つと、ページ上部に公開URLが表示されます
   （例：`https://ユーザー名.github.io/リポジトリ名/`）

> 💡 このリポジトリに変更をpushするたびに、GitHub Pagesは自動で更新されます。

---

## 13. 公開後のURLの確認方法

1. GitHubのリポジトリ画面 → 「Settings」→「Pages」を開く
2. ページ上部に「Your site is live at ～」という緑色の表示があれば、そこにURLが
   表示されています
3. そのURLをコピーして、ブラウザで開けば公開状況を確認できます
4. Instagramのプロフィール欄やリンク集ツールに、そのURLを貼り付けてください

## 14. よくあるエラーと対処方法

| 症状 | 原因の可能性 | 対処方法 |
|---|---|---|
| ページが真っ白になる | `content.js` の書き方に誤り（カンマの消し忘れなど） | 直前に保存した内容に戻し、1か所ずつ変更して確認する |
| 文章が反映されない | ブラウザのキャッシュが残っている | スマホ・PCともに再読み込み（強制リロード）する |
| コピーボタンが反応しない | 古いブラウザ、またはページを`file://`で直接開いている | GitHub Pages公開後のURL（`https://`）で確認する |
| 動画が再生されない | 動画ファイルの場所やファイル名が違う | `content.js` のパスと、実際のファイル名が一致しているか確認する |
| 公開URLが404になる | GitHub Pagesの設定がまだ反映されていない | 数分待ってから再度アクセスする |
| 画像が表示されない | ファイル名の大文字・小文字違い、拡張子違い | `assets/images/` 内の実際のファイル名と `content.js` の記載を見比べる |

## 15. スマートフォン表示の確認方法

- 実際にスマートフォンのブラウザで公開URLを開いて確認するのが一番確実です
- パソコンで確認したい場合は、Google Chromeの「検証」機能（右クリック→検証）から
  スマホ画面のシミュレーション表示に切り替えられます
- 特に確認したいポイント
  - 文字が小さすぎないか
  - ボタンが押しやすい大きさになっているか
  - 横スクロールが発生していないか
  - コピーボタンを押すと「コピーしました」と表示されるか

## 16. 元のテンプレートを壊さない運用方法

- **必ず「Use this template」で複製してから**編集してください
- 元のテンプレートリポジトリ（このリポジトリ）は、できるだけ触らないようにしましょう
- 新しい特典を作るたびに、新しいリポジトリを作る運用にすると、
  過去の特典ページもそのまま残しておけます
- 迷ったときのために、公開して問題なかった `content.js` は
  自分のパソコンにも保存しておくと安心です

## 技術的なメモ（参考情報）

- ビルド（変換作業）は一切不要です。HTML・CSS・JavaScriptだけで動く「静的サイト」です
- React・Next.js・Vue・データベース・サーバーは使用していません
- 外部の有料サービスへの依存はありません
- 文字のフォントは、各OSに標準で入っているフォント（システムフォント）を使用しているため、
  追加の読み込みなしで綺麗な日本語表示になります
